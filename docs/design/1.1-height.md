# 1.1 Height

*Status: **draft, being written lesson by lesson.** Started 20 November 2026. Part of [Stage 1](1.0-how-the-world-is-made.md).*

## What it does

Gives the height of the ground, in metres, at any point (x, y) in the world. Below 0 m is sea. It's a **formula**: nothing is stored, and the same seed always gives the same land. Everything else in Stage 1 (temperature, rain, rivers, biomes) is built on it.

## A. 2D value noise

### The idea

Put a grid over the world with grid points every `size` km. Give every grid point a random height from the hash: `hash(i, j, seed)`, a number between 0 and 1 that's always the same for the same point. Every point on the map sits inside one grid square with four corners. **Blend the four corner heights** according to how close the point is to each corner.

It's the 1D blend from September, done twice: once along x, then once along y.

### The formula

```
i = floor(x / size)          the grid column to the left of the point
j = floor(y / size)          the grid row below the point
fx = x / size − i            how far across the square, 0 to 1
fy = y / size − j            how far up the square, 0 to 1
u = s(fx),  v = s(fy)        smoothstep both, so there are no creases

h00 = hash(i,   j)           bottom-left corner
h10 = hash(i+1, j)           bottom-right
h01 = hash(i,   j+1)         top-left
h11 = hash(i+1, j+1)         top-right

bottom = h00 + (h10 − h00) × u      blend along the bottom edge
top    = h01 + (h11 − h01) × u      blend along the top edge
height = bottom + (top − bottom) × v    blend between the two, upwards
```

### Worked example

`size` = 10 km, point (23, 37). Suppose the hash gave these corner heights:

```
 (20,40) h01 = 0.4 ─────── h11 = 0.6 (30,40)
           │                    │
           │      • (23,37)     │
           │                    │
 (20,30) h00 = 0.2 ─────── h10 = 0.8 (30,30)
```

| Step | Working | Result |
|---|---|---|
| Grid square | i = floor(2.3) = 2, j = floor(3.7) = 3 | corners at x = 20, 30 and y = 30, 40 |
| Fractions | fx = 2.3 − 2, fy = 3.7 − 3 | fx = 0.3, fy = 0.7 |
| Smoothstep | u = 0.3² × (3 − 0.6) = 0.09 × 2.4; v = 0.7² × (3 − 1.4) = 0.49 × 1.6 | u = 0.216, v = 0.784 |
| Bottom edge | 0.2 + (0.8 − 0.2) × 0.216 = 0.2 + 0.1296 | 0.3296 |
| Top edge | 0.4 + (0.6 − 0.4) × 0.216 = 0.4 + 0.0432 | 0.4432 |
| Upwards | 0.3296 + (0.4432 − 0.3296) × 0.784 = 0.3296 + 0.0891 | **0.4187** |

**Check: the order doesn't matter.** Blend up the left and right edges first, then across:
- left = 0.2 + (0.4 − 0.2) × 0.784 = 0.3568
- right = 0.8 + (0.6 − 0.8) × 0.784 = 0.6432
- 0.3568 + (0.6432 − 0.3568) × 0.216 = **0.4187**

Same answer. That's not luck, as the next section shows.

### The same thing as four weights

Multiply the formula out and it becomes one weighted average of the four corners:

```
height = h00 × (1−u)(1−v)  +  h10 × u(1−v)  +  h01 × (1−u)v  +  h11 × uv
```

- **The four weights always add up to 1.** So the height is always between the lowest and highest corner, and never overshoots.
- **Each weight is the area of the rectangle diagonally opposite that corner** (in the smoothstepped u, v space). The nearer the point is to a corner, the bigger the opposite rectangle, so the more that corner counts.
- It's symmetric in x and y, which is why the order of blending didn't matter.

In the example (u = 0.216, v = 0.784):

| Corner | Weight | Working | Weight × height |
|---|---|---|---|
| h00 = 0.2, bottom-left | (1−u)(1−v) | 0.784 × 0.216 = 0.169 | 0.034 |
| h10 = 0.8, bottom-right | u(1−v) | 0.216 × 0.216 = 0.047 | 0.037 |
| h01 = 0.4, top-left | (1−u)v | 0.784 × 0.784 = **0.615** | 0.246 |
| h11 = 0.6, top-right | uv | 0.216 × 0.784 = 0.169 | 0.102 |
| | | sum = 1.000 | **0.419** ✓ |

The point (23, 37) is near the **top-left** corner, so top-left gets by far the biggest weight (0.615).

**Engineering connection:** without the smoothstep (u = fx, v = fy), these are exactly the **bilinear shape functions of a 4-node quadrilateral element** in finite element analysis: N₁ = (1−ξ)(1−η) and so on. Value noise is FE interpolation of random nodal values. The smoothstep is what makes the slope continuous across element edges, which plain bilinear elements don't give you (they're only C⁰).

### From 0–1 to −1 to +1

The hash gives 0 to 1, so the noise averages 0.5. For land, we want bumps that go **up and down** around zero, so we use `n = 2 × height − 1`, which runs from −1 to +1 with an average of 0. Then `roughness × n` is a bump of up to ± roughness metres.

### What it looks like, and its flaw

Soft, rounded blobs, one per grid square. **The flaw:** look closely and you can see the grid. Blobs line up along the grid lines, and every grid point is a flat spot (the slope is zero there in both directions, as worked out for 1D in September). Octaves (lesson B) hide it a bit; simplex noise (lesson C) fixes it properly.
