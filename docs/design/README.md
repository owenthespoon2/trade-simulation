# Design notes

One note per system, written **before** the system is built. Each one is the explanation of its code, and changes whenever the code does.

## How a note is laid out

1. **What it does:** one paragraph, in plain words.
2. **Inputs and outputs:** what it reads, what it produces, with units.
3. **The maths and logic:** every formula and every step, explained.
4. **Worked example:** real numbers, by hand, which the code's tests then check.
5. **Simplifications:** what we left out for now, and what would make it more realistic later.
6. **Questions and answers:** anything that came up while going through it.
7. **Status:** draft → understood → built → checked.
